# Задачи по внедрению новой логики комнаты

## Цель

Перевести 2D-редактор комнаты на простую и предсказуемую модель:

- `drag` стены и `Ctrl + drag` вершины остаются черновыми инструментами наброска
- точное редактирование выполняется только через `input`
- при `input` меняется только выбранная стена
- остальной хвост комнаты не меняет свои собственные длины и углы, а только сдвигается
- `closing wall` пересчитывается последней и забирает всю невязку
- все параметры комнаты должны быть доступны через отдельный popup

---

## Что считаем правильной целевой моделью

### Черновой режим

- Обычный `drag` стены оставляем как есть
- `Ctrl + drag` синей точки оставляем как есть
- Эти режимы нужны только для грубого наброска формы комнаты
- В черновом режиме не требуется точная геометрия

### Точный режим

- Точный режим работает только через `input`
- Есть два вида точного ввода:
  - изменение длины стены
  - изменение угла стены
- После точного ввода:
  - выбранная стена получает новое значение
  - хвост комнаты смещается как единое целое
  - `closing wall` пересчитывается последней

---

## Основные задачи

## Шаг 1. Зафиксировать exact-математику комнаты

### Задача

Определить одну стабильную модель вычислений для комнаты.

### Нужно сделать

- Ввести единый `ordered chain` стен комнаты
- Зафиксировать стабильный порядок обхода стен по контуру
- Для каждой обычной стены явно понимать:
  - кто предыдущая стена
  - кто следующая стена
  - где начинается хвост после выбранной стены
- Принять единое правило exact-редактирования:

```
input -> меняем выбранную стену -> двигаем хвост -> пересчитываем closing wall
```

### Результат

Есть один источник истины для exact-логики комнаты.

---

## Шаг 2. Определить механику angle input

### Задача

Убрать баги редактирования угла рядом с `closing wall`.

### Нужно сделать

- Перестать использовать `closing wall` как опорную стену для вычисления нового угла
- Для angle input фиксировать `incomingDir` как snapshot в момент начала редактирования
- При применении угла:
  - фиксировать `point0` выбранной стены
  - сохранять длину стены
  - строить новый `point1` по `incomingDir` и введённому углу
  - сдвигать хвост на `delta = newPoint1 - oldPoint1`
  - затем пересчитывать `closing wall`

### Результат

Angle input начинает работать одинаково для любой обычной стены, включая стены рядом с `closing wall`.

---

## Шаг 3. Привести length input к той же модели

### Задача

Сделать длину и угол частью одной exact-схемы.

### Нужно сделать

- Проверить текущий `applyWallLengthMm`
- Оставить в нём только нужную механику:
  - фиксируем `point0`
  - строим новый `point1` по текущему направлению и новой длине
  - считаем `delta`
  - двигаем хвост
  - пересчитываем `closing wall`
- Убрать из этой логики всё, что противоречит новой модели

### Результат

Length input и angle input работают по одному и тому же принципу.

---

## Шаг 4. Упростить UI для угла

### Задача

Убрать лишние элементы старой концепции из angle flow.

### Нужно сделать

- Убрать `dragAngleStepDeg` из пользовательского сценария
- Убрать второй input из `AngleInputModal`
- Оставить в модалке только ввод угла
- Исправить позиционирование `AngleInputModal`, чтобы popup не выходил за пределы viewport

### Результат

UI редактирования угла становится простым и соответствует новой модели.

---

## Шаг 5. Не ломать draft-режим

### Задача

Сохранить удобный набросок комнаты.

### Нужно сделать

- Не переписывать текущий `drag` стены
- Не убирать `Ctrl + drag` вершины
- Не пытаться сделать их частью exact-математики
- Явно считать их черновыми инструментами

### Результат

Пользователь по-прежнему может быстро набросать форму комнаты до точного ввода размеров.

---

## Шаг 6. Сделать popup со всеми параметрами комнаты

### Задача

Добавить отдельный popup со списком всех стен и их параметров.

### Нужно сделать

- Использовать существующую popup-систему
- Создать новый popup по тому же паттерну, что и текущие popup-компоненты
- Список стен генерировать автоматически, проходясь по текущему состоянию комнаты
- Лучше всего строить список по `ordered chain`
- Для каждой стены выводить строку:
  - название или номер стены
  - input длины
  - input угла
  - признак `closing wall`
- Для `closing wall` поля должны быть disabled
- Эти input должны вызывать ту же exact-логику, что и input на сцене

### Результат

Появляется единый popup параметров комнаты без отдельной математики и без дублирования логики.

---

## Шаг 7. Зачистить лишнее после стабилизации

### Задача

Убрать остатки старой усложнённой концепции.

### Нужно сделать

- Удалить или изолировать всё, что связано с `pin`
- Удалить или изолировать всё, что связано с `anchor`
- Удалить или изолировать лишние chain-утилиты, которые больше не нужны новой модели
- Оставить только одну понятную exact-логику комнаты

### Результат

Код перестаёт содержать параллельные концепции и становится проще поддерживать.

## Порядок внедрения

Рекомендуемый порядок работ:

1. `ordered chain + incomingDir`
2. `angle input`
3. `length input`
4. `angle modal cleanup`
5. `room params popup`
6. зачистка лишнего

---

## Scope первой рабочей итерации

В первую рабочую итерацию должны войти:

- стабильная exact-логика угла для любой обычной стены
- length input по той же модели
- корректный пересчёт `closing wall`
- popup со всеми параметрами комнаты
- сохранение текущего удобного draft-режима через `drag` и `Ctrl + drag`

---

## Что не делаем в этой задаче

В рамках текущей итерации не делаем:

- новый solver комнаты
- распределение невязки по нескольким стенам
- `pin` и `anchor` как пользовательские сущности
- обязательную квантизацию углов
- усложнение draft-режима

---

## Критерий готовности

Фича считается готовой, если:

- пользователь может мышкой набросать комнату
- пользователь может точно задать длину любой обычной стены
- пользователь может точно задать угол любой обычной стены
- случай рядом с `closing wall` больше не даёт багов
- `closing wall` всегда пересчитывается как итоговая замыкающая стена
- popup параметров комнаты показывает все стены и позволяет редактировать их через те же exact-handlers
