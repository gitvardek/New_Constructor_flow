# Хоткеи

Одна система горячих клавиш на приложение: один слушатель, стек скоупов,
декларативный реестр.

## Как добавить хоткей

1. Запись в `registry/hotkeys.config.ts` — `HOTKEY_IDS` + `HOTKEYS`
   (комбинация, скоуп, подпись для UI).
2. Регистрация обработчика там, где живёт действие:

```ts
import { useHotkey, HOTKEY_IDS } from '@/features/hotkeys'

useHotkey(HOTKEY_IDS.MY_ACTION, () => doSomething())
```

Комбинация и скоуп подтянутся из реестра, снятие — при размонтировании.
Обработчик должен вызывать существующую команду, а не повторять её логику:
хоткей и кнопка обязаны делать ровно одно и то же.

## Скоупы

Скоуп не флаг, а запись в стеке. Кладёт её тот компонент, который этот скоуп
и представляет:

```ts
import { useHotkeyScope, SCOPES } from '@/features/hotkeys'

useHotkeyScope(SCOPES.POPUP, { exclusive: true, active: () => isOpen.value })
```

Поиск биндинга идёт сверху вниз, `global` опрашивается последним. `exclusive`
обрывает поиск на своей записи — так модальное окно глушит хоткеи канваса
даже для комбинаций, которые само не занимает.

## Зажатые модификаторы

Удержание Ctrl/Shift — не комбинация: диспетчер такие нажатия отбрасывает и
`keyup` не слушает вовсе. Для «зажат ли сейчас» есть `ModifierTracker`:

```ts
import { modifiers } from '@/features/hotkeys'

const release = modifiers.subscribe(state => {
  controls.screenSpacePanning = state.ctrl || state.meta
})
```

Слушатели включены, пока есть подписчики. Состояние сбрасывается на `blur` и
`visibilitychange` — иначе alt-tab с зажатым Shift оставляет флаг навсегда.

## Правила, на которых держится предсказуемость

- **Один слушатель.** `HotkeyDispatcher` на `window`, фаза capture. Новых
  глобальных `addEventListener('keydown')` в приложении быть не должно.
- **Первый подошедший побеждает**, скоупы — сверху вниз. Внутри одного скоупа
  главнее тот, кто зарегистрирован позже: только что смонтированный компонент
  перекрывает прежний, а после размонтирования прежний снова оживает.
- **`false` из обработчика = «не моё»**: диспетчер идёт к следующему кандидату
  и не вызывает `preventDefault`. Так Esc отдаёт управление нативному
  `<dialog>`.
- **Конфликты не молчат.** Две регистрации на одну комбинацию в одном скоупе
  дают `console.warn` с обоими id (только в dev).
- **Клавиша берётся из `event.code`**, не из `event.key` — иначе хоткеи
  отваливаются в русской раскладке. Поэтому в конфиге пишется `shift+1`, а не
  `!`.
- **`stopPropagation` по умолчанию выключен.** Диспетчер стоит на capture, и
  глушение сломало бы `@keydown` внутри компонентов. Включать осознанно.
- **Открытая модалка глушит всё под собой.** `Modal.vue` кладёт `popup` как
  `exclusive`, пока открыт его `<dialog>`: Delete в редакторе УМ не удалит
  редактируемый товар. Esc от этого не страдает (его обработчик и так отдаёт
  управление нативному диалогу), а `Ctrl+Z` при открытой модалке не работает —
  намеренно.
- **Ввод защищён централизованно** (`guards.ts`): текстовые поля,
  `contenteditable`, `SELECT`, IME-композиция, автоповтор.

## Состав

| Файл | Назначение |
|---|---|
| `types.ts` | типы биндингов, контекста, метаданных |
| `core/combo.ts` | строка комбинации -> канонический вид, `mod` по ОС, формат для UI |
| `core/keyboardEvent.ts` | `KeyboardEvent` -> комбинация (по `event.code`) |
| `core/scopeStack.ts` | стек скоупов, активный путь |
| `core/HotkeyRegistry.ts` | биндинги, разрешение, детект конфликтов |
| `core/HotkeyDispatcher.ts` | единственный слушатель, гарды |
| `core/ModifierTracker.ts` | состояние зажатых Ctrl/Alt/Shift/Meta |
| `guards.ts` | поля ввода, открытый нативный `<dialog>` |
| `registry/scopes.ts` | скоупы приложения |
| `registry/hotkeys.config.ts` | реестр хоткеев + окна, которые Esc не закрывает |
| `composables/*` | регистрация и скоупы на время жизни компонента |
| `commands/useHotkeyCommands.ts` | мост к командам без своего состояния, ставится в `DefaultLayout.vue` |
| `registerById.ts` | регистрация без Vue — для движков |
| `runtime.ts` | синглтоны ядра |
| `useHotkeysStore.ts` | реактивная витрина: скоупы, список, переопределения |

`core/*` не зависит от Vue и Pinia — тем же ядром могут пользоваться движки
(`Application`, `Constructor2D`), это обычные TS-классы.

## Что сейчас зарегистрировано

- `popup.closeTop` — `Esc` в скоупе `popup`, закрывает последнее открытое
  окно `MainPopUp`. Вне открытого окна биндинг недостижим, потому и живёт в том
  скоупе, который закрывает. Не трогает нативные `<dialog>` и окна из
  `ESC_LOCKED_POPUPS`.
  У нативного диалога Esc обрабатывает браузер, поэтому модалке с уборкой в
  `@close-modal` нужен флаг `handle-escape`: без него окно закрывается молча,
  уборка не выполняется (так ломался редактор столешницы).
- `history.undo` / `history.redo` — `Ctrl+Z` и `Ctrl+Y` (плюс `Ctrl+Shift+Z`).
  Зарегистрированы в `MainHeader.vue` и вызывают те же `prevAction`/`nextAction`,
  что кнопки истории; `enabled` повторяет их условия показа и блокировки, так
  что хоткей не сработает там, где кнопка погашена.
- `plan2d.deleteActive` — `Delete` / `Backspace` в скоупе `plan2d`: удаляет
  активную стену или проём. Регистрируется самим движком
  (`Constructor2D/methods/events/hotkeys`), снимается в его `destroy()`.
  Если удалять нечего — возвращает `false` и событие остаётся свободным.
- `product.duplicate` / `product.delete` — `Ctrl+C` и `Delete`/`Backspace`
  в скоупе `scene3d`: дубль и удаление выделенного товара. Зарегистрированы в
  `views/The3D.vue` и вызывают те же `duplicateProduct`/`removeModel`, что
  кнопки контроллера товара; `enabled` повторяет условие их показа
  (`canModifySelected`). Удаление без подтверждения — откат через `Ctrl+Z`.
- `project.save` — `Ctrl+S`, вызывает ту же команду, что кнопка сохранения в
  тулбаре. Зарегистрирован в `QuickActionsToolbar.vue`, а не в
  `useHotkeyCommands`: диалоги сохранения привязаны к рефам конкретного
  экземпляра `useQuickActionsToolbar`, у второй копии composable они пустые.
  Работает и при фокусе в поле (`allowInInput`), гаснет, пока идёт сохранение.
- `toolbar.ruller` — `Alt+R`, **демо-биндинг**: вызывает ту же команду, что
  кнопка линейки в тулбаре. Снимается удалением блока в
  `commands/useHotkeyCommands.ts` и записи в реестре.

Скоупы кладёт тот, кому они принадлежат: `plan2d` — движок `Constructor2D` на
время своей жизни (создаётся в `views/Constructor2D.vue` при монтировании),
`scene3d` — сама `views/The3D.vue`, `popup` — `Modal.vue` (пока открыт его
`<dialog>`) и `MainPopUp.vue` (пока показан оверлей).

Модификаторы: камера подписана на `ctrl/meta` (панорамирование в плоскости
экрана), `Constructor2D` — на `shift/ctrl` (пишет в `state.keys`, их читают
`Layers/Planner` и `Layers/StartPointActiveObject`).

## Подсказки в UI

`useHotkeysStore().describe(id)` отдаёт готовую подпись с комбинацией —
«Отменить действие (Ctrl + Z)», с учётом переопределений. Так подписаны кнопки
истории в шапке.

## Не сделано

- **Undo/redo всё ещё живут в `MainHeader.vue`** вместе со своим состоянием
  (`historyActions`, `curActionCount`, `restorLength`, ссылка на `Application`).
  Хоткею выносить их не потребовалось — он зарегистрирован там же, — но для
  вызова undo откуда-то ещё состояние придётся поднять в стор.
- **Ремаппинг** есть как точка расширения (`useHotkeysStore.setCombo`), но без
  хранения и UI: комбинация живёт только в памяти сессии. К биндингам движков
  (`registerById`) переопределения не применяются вовсе — стор это Vue-слой.
- **Признак «закрывается по Esc»** лежит в `ESC_LOCKED_POPUPS`, хотя его место
  — в `POPUP_CONFIG` рядом с каждым окном.
- **Скоуп `umEditor`** объявлен, но никем не кладётся: он понадобится, когда у
  редактора модуля появятся свои хоткеи. Пока открытый редактор просто глушит
  всё под собой как модалка.
- **Порядок в стеке важнее `exclusive`**: скоуп, положенный позже открытого
  модального окна, окажется выше него и снова станет доступен. Случай узкий —
  навигация на `/2d` или `/3d` при открытом окне, когда вид монтируется
  заново. Чинится либо приоритетами вместо порядка в `scopeStack`, либо
  перекладыванием скоупа окна наверх при смене маршрута.
