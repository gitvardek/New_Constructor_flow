# Концепт: Редактор комнаты 2D

## Главная идея

Редактор должен быть максимально простым и предсказуемым.

Пользователь работает в двух режимах:

- `drag` — свободно набрасывает форму комнаты мышкой
- `input` — точно задаёт длину или угол выбранной стены

Ключевой принцип:

**При точном вводе через input меняется только выбранный параметр и автоматически пересчитывается только одна замыкающая стена.**

Остальные стены могут сдвинуться на холсте как единый хвост, но:

- не должны менять свою длину
- не должны менять свои собственные углы
- не должны пересчитываться по значениям

Вся остаточная невязка всегда уходит в `closing wall`.

---

## Продуктовая модель

### Комната

Комната — это замкнутый контур из стен.

Одна из стен всегда помечена как замыкающая:

- `isClosing: true`
- её геометрия вычисляется автоматически
- пользователь не редактирует её длину и угол вручную

Все остальные стены — обычные редактируемые стены.

---

## Базовые правила

### 1. Drag

`Drag` нужен только для грубого наброска формы.

Поведение:

- пользователь тянет любую стену как хочет
- геометрия может меняться свободно
- соседние стены ведут себя по текущей drag-логике редактора
- замыкающая стена во время drag ведёт себя как обычная стена

Важно:

- drag не обязан сохранять точные длины и углы
- drag не запускает сложные solver-механики
- drag не требует `pin`, `anchor`, `chain propagation`

Идея простая:

**мышкой набрасываем форму, точность задаём только инпутами**

---

### 2. Input длины

При вводе длины стены:

- меняется длина выбранной стены
- остальные стены не меняют свои длины
- остальные стены не меняют свои углы
- они могут только сдвинуться на плоскости как единый хвост
- после этого пересчитывается замыкающая стена

То есть input не "решает комнату целиком", а делает локальное точное изменение и отдаёт остаток в `closing wall`.

---

### 3. Input угла

При вводе угла стены:

- меняется угол выбранной стены в её стартовой вершине
- остальные стены не меняют свои длины
- остальные стены не меняют свои внутренние углы
- они могут только сместиться на холсте как единый связанный хвост
- после этого пересчитывается замыкающая стена

Замыкающая стена снова принимает на себя всю невязку.

---

## Что НЕ нужно в этой концепции

В рамках текущей модели не нужны как продуктовые сущности:

- `pin`
- `anchor`
- `chain propagation` с поиском ближайшего якоря
- сложные solver-алгоритмы для input
- обязательная квантизация углов
- ghost preview

Если внутри кода понадобится технически "сдвинуть хвост", это допустимо, но это не отдельная пользовательская механика и не часть продуктового UX.

---

## Closing Wall

### Роль

`Closing wall` нужна только для того, чтобы комната оставалась замкнутой после точного редактирования.

Она:

- автоматически соединяет конец хвоста с началом комнаты
- хранит остаточную геометрическую невязку
- служит визуальным индикатором качества измерений

### Ограничения

Для `closing wall`:

- длина read-only
- угол read-only
- split запрещён
- прямое редактирование через input запрещено

### Поведение при drag

Во время `drag` замыкающая стена не особая.

Она может двигаться как обычная стена в составе текущей drag-логики.  
Автовычисление `closing wall` относится именно к режиму точного ввода через input.

---

## Popup параметров комнаты

Нужен отдельный popup со всеми параметрами комнаты.

Это обязательная часть задачи.

### Что показывает popup

Popup строится автоматически по текущему набору стен комнаты.

Для каждой стены нужна строка:

- имя или номер стены
- длина
- угол
- признак `closing wall`

### Правила работы popup

- список стен не хардкодится
- количество строк зависит от текущего числа стен
- обычные стены редактируются
- `closing wall` отображается, но её поля disabled
- popup использует ту же логику редактирования, что и инпуты на сцене

Идея одна:

```
Инпут на сцене
Инпут в popup параметров комнаты
→ вызывают один и тот же механизм изменения стены
→ затем пересчитывается closing wall
```

---

## Пользовательский сценарий

1. Открывается базовая комната
2. Пользователь мышкой набрасывает форму помещения
3. При необходимости добавляет новые стены
4. Потом по очереди вводит точные длины
5. Потом вводит точные углы
6. Смотрит на результат замыкающей стены
7. Если замыкающая выглядит странно, значит где-то ошибка в измерениях

---

## Валидация

Нужна простая и понятная валидация:

- нельзя допускать самопересечение контура
- нельзя допускать нулевую или отрицательную длину стены
- можно показывать warning для слишком коротких стен
- можно показывать warning для слишком острых углов
- warning на `closing wall` означает: "Проверьте измерения"

Валидация не должна превращать UX в solver.

---

## Что должно получиться

В результате пользователь получает понятную модель:

- мышкой — быстро набрасывает форму
- инпутами — точно вводит измерения
- редактор не "думает за пользователя" слишком много
- все расхождения собираются в одной замыкающей стене
- все параметры комнаты доступны и на сцене, и в отдельном popup

Это и есть целевая концепция текущей версии.
