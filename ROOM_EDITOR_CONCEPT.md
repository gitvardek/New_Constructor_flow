# Концепт: Редактор комнаты 2D

## Философия

Пользователь строит замкнутый контур комнаты. Комната — это всегда замкнутый полигон.
Пользователь не думает о "склейке стен" — он думает о форме комнаты.

Ключевой принцип: **одна стена всегда вычисляется автоматически** (замыкающая). Это снимает математическое противоречие замкнутого контура — пользователь свободно задаёт все остальные стены, а замыкающая "добирает" остаток.

Сценарий: пользователь переносит реальную квартиру в шаблон. Накидывает форму, потом по очереди выставляет точные углы и длины. Если измерения верные — замыкающая стена сойдётся корректно. Если она выглядит криво — где-то ошибка в измерениях.

---

## Модель данных

### Комната
Замкнутый контур из N стен. Стены — упорядоченная цепочка:

```
W1 → W2 → W3 → ... → W(N-1) → W_closing → (back to W1)
```

### Обычная стена (W1 ... W(N-1))
- `point0` — начальная вершина (shared с предыдущей стеной)
- `point1` — конечная вершина (shared со следующей стеной)
- `length` — длина в мм, задаётся пользователем
- `angleDeg` — угол в вершине point0, задаётся пользователем (свободное значение, без snap)
- `isPinned: boolean` — зафиксирована ли стена (chain propagation останавливается)
- Может быть разделена (split)
- Доступна для drag и инпутов

### Замыкающая стена (W_closing)
- `isClosing: boolean = true`
- `point0` и `point1` — **вычисляются автоматически**
- `length` и `angleDeg` на обоих концах — **read-only**, только для отображения
- **Нельзя разделить (split)**
- **Нельзя редактировать через инпуты**
- Визуально отличается (пунктирная линия или другой цвет)
- Если её вычисленные параметры попадают в зону warning — подсвечивается жёлтым с tooltip "Проверьте измерения"

## Операции

### 1. Drag стены

- Текущее поведение (`updateMergeWallProperties`) — **не меняем**
- Свободный drag, соседи тянутся, замыкающая едет как обычная стена
- Никакого ghosting, никакого snap, никакой chain propagation
- Используется для грубого наброска формы комнаты

**Drag = фаза набросков. Точность — только через инпуты.**

---

### 2. Инпут длины стены

- `point0` фиксируется (anchor)
- `point1` двигается вдоль текущего направления на новую длину
- Propagation: в сторону ближайшего якоря от `point1`
- Замыкающая пересчитывается

---

### 3. Инпут угла стены

- `point0` фиксируется
- Стена и цепочка до ближайшего якоря поворачиваются как жёсткое тело вокруг `point0`
- Замыкающая пересчитывается
- Значение квантизуется до ближайшего шага (`angleStepDeg`)

Углы замыкающей — read-only, только отображаются.

---

### 4. Панель параметров помещения

Генерируется **автоматически** по текущему состоянию комнаты — количество строк = количество стен. Не нужно хардкодить стены.

Список всех стен с теми же инпутами. Источник данных другой, логика одна:

```
Инпут на сцене (ПКМ → контекстное меню) ──┐
                                            ├──► chain propagation ──► recalculateClosingWall()
Инпут в отдельном фрейме (панель стен) ────┘
```

Структура строки в панели:
- Номер/название стены (W1, W2 ... W_closing)
- Длина (мм) — disabled если `isClosing`
- Угол (°) — disabled если `isClosing`
- Иконка пина — toggle `isPinned`
- Жёлтый фон строки — если стена в warning
- Иконка замка — если `isClosing`

Правила disabled идентичны сцене. Количество строк меняется при split/удалении стены — панель перерисовывается автоматически.

---

### 5. Пиннинг стен

Любая обычная стена может быть зафиксирована. Chain propagation останавливается на ближайшей запинненой стене.

```
W_closing → W1[pin] → W2 → W3[edit] → W4 → W5[pin] → W6 → W_closing

Меняем W3 → ищем ближайший якорь в обе стороны:
  Влево: W2 → W1[pin]  (2 шага)  ← ближе
  Вправо: W4 → W5[pin]  (2 шага)
  При равенстве — предпочитаем сторону с пином (не трогаем замыкающую)
```

Замыкающая = глобальный fallback если нет ни одного пина.

**UI:** иконка замочка на стене при выборе (или Shift+клик). Пин — сессионное состояние, не сохраняется в store.

---

### 6. Split стены (добавить вершину)

- Правый клик → "Добавить точку" → стена делится пополам
- Split замыкающей **запрещён**
- Минимальное количество обычных стен = 3

---

### 7. Вращение сцены

- Поворот **PIXI stage** — геометрия не меняется, никакого пересчёта
- Аналог вращения камеры в 3D
- Текстовые labels на стенах получают counter-rotation чтобы текст оставался читаемым

---

## Snap и квантизация

**Нет обязательного snap. Нет квантизации.**

- Drag — полностью свободный
- Инпуты — пользователь вводит точное значение, оно применяется как есть
- Никаких шагов углов, никакой сетки длин

Ctrl и Alt для snap — не реализуются (можно добавить позже как отдельную задачу).

---

## Валидация и предупреждения

### Конфиг лимитов
```typescript
const roomValidationConfig = {
  minAngleDeg: 15,
  maxAngleDeg: 345,
  minWallLengthMm: 100,
}
```

### Правила
- **Жёсткий запрет:** самопересечение контура
- **Жёсткий запрет:** длина стены ≤ 0
- **Предупреждение (жёлтая стена + tooltip):** угол < minAngleDeg или > maxAngleDeg
- **Предупреждение:** длина < minWallLengthMm
- **Предупреждение на замыкающей:** если её вычисленные параметры в зоне warning → "Проверьте измерения"

### Валидация инпутов на лету
На каждый keystroke — симуляция изменения (без коммита), проверка результата. Блокируется только при жёстких нарушениях. При фокусе на поле — показывается допустимый диапазон (`от 200мм до 4500мм`).

## Типичный сценарий использования

1. Открывается прямоугольная комната (3 обычных стены + 1 замыкающая)
2. Пользователь добавляет вершины (split) чтобы набросать форму квартиры
3. Вращает сцену если нужно чтобы ориентация совпала с реальной
4. По очереди выставляет точные углы через инпут (на сцене или в панели)
5. По очереди выставляет точные длины
6. Смотрит на замыкающую — если нормальная, измерения верные
7. Если замыкающая жёлтая и странная — ищет ошибку в измерениях

## Шаг 0: Ресёрч кода и карта изменений

**Цель:** понять точно что комментируем, что переиспользуем, что пишем заново. Ничего не менять.

### Закомментировать
- `getStrictStepWallMoveSimulationResult` — solver 120 кандидатов
- `hasAnyRoomAngleStepReached`
- `dragAngleStepDeg` — глобальный параметр шага
- Блок в `handlerStageMouseMove` где вызывается strict solver (~строки 82-100)

### Переиспользовать как есть
- `getRoomContour()` — основа для пересчёта замыкающей и порядка цепочки
- `getWallMoveSimulationResult()` — основа для валидации инпутов
- `updateMergeWallProperties()` — обновление соседей
- `calculatePositionPointsWall()` — пересчёт 4 точек стены
- `splitWallIntoTwo()` — только добавить проверку на isClosing
- `getMergeWallsIDForUpdate()` — основа для BFS в обе стороны (поиск ближайшего якоря)
- `updateRoomStore()`

### Написать новое
- `getOrderedChain(roomId)` — упорядоченный массив стен (через getRoomContour)
- `getNearestAnchor(wallId, direction)` — BFS до ближайшего isPinned или isClosing
- `getChainToNearestAnchor(wallId)` — подмассив цепочки с выбором направления
- `applyRigidChainShift(chain, deltaX, deltaY)` — сдвиг как жёсткое тело
- `applyRigidChainRotation(chain, pivot, angleDelta)` — поворот вокруг точки
- `recalculateClosingWall(roomId)` — пересчитать point0/point1 замыкающей
- `simulateWallChange(wallId, param, value)` — симуляция для валидации

### ⚠️ Критические моменты для обсуждения до шага 1

**Двери и окна при сдвиге цепочки**
Сейчас хранят абсолютные координаты. При chain propagation стены физически смещаются — двери/окна должны смещаться вместе. Нужно понять как они привязаны к стенам.

**Canonical chain order**
`mergeWalls` — граф, не массив. Нужно убедиться что порядок из `getRoomContour()` стабилен после split, init, reload.

**Сериализация isClosing**
`updateRoomStore()` → `IWallData` — поля `isClosing` нет. После перезагрузки нужно восстановить. Варианты: добавить поле в IWallData, или восстанавливать по правилу (последняя стена контура).

## Шаг 9 (v3, не делаем сейчас): FABRIK для drag

**Статус:** концепт на будущее.

**Проблема:** при drag вся цепочка сдвигается как жёсткое тело. FABRIK распределяет движение равномерно по всем стенам — комната "дышит" плавно.

**Важно:** только для drag. Точный инпут всегда через жёсткую chain propagation.

Источник: [FABRIK paper](https://andreasaristidou.com/FABRIK)

## Постмортем первой итерации реализации

### Проблема 1: Ghost и 120-кандидатов
**Что случилось:** В коммите `e5e7e4a` при драге запускался solver из 120 кандидатов для квантизации угла. Появлялся визуальный ghost-preview.  
**Эффект:** Артефакты, лаги, запутанный UX.  
**Решение:** Полностью убрать. Drag работает напрямую, без preview-слоя и без solver.  
**Статус:** Откатились до `c2602aa`, проблемы нет.

---

### Проблема 2: Perpendicular-only drag (Шаг 4 по плану)
**Что случилось:** Реализовали drag только вдоль перпендикуляра к стене (параллельный сдвиг). Стена двигалась только в одном направлении.  
**Эффект:** Невозможно свободно набросать форму комнаты. Нарушался весь UX "набросал — уточнил".  
**Вывод:** Параллельный сдвиг — правильная механика для **инпутов** (точная настройка), но **не для drag**. Drag должен быть свободным 2D.  
**Решение:** Drag = свободный 2D, как в `c2602aa`. Параллельный сдвиг — только в `eventModifyWall` (length input) и `setActiveWallAngleByPoint0` (angle input).

---

### Проблема 3: Chain propagation во время drag
**Что случилось:** При перетаскивании стены запускалась цепная пропагация — следующие стены сдвигались как жёсткое тело.  
**Эффект:** Стены до цепи не двигались → углы разрывались → контур ломался. Визуально: стены "разъезжались".  
**Вывод:** Chain propagation конфликтует с `updateMergeWallProperties` — нельзя одновременно тянуть соседей и сдвигать цепь.  
**Решение:** Никакой chain propagation во время drag. Drag → `updateMergeWallProperties` (старое поведение, соседи растягиваются). Chain propagation → только в инпутах.

---

### Проблема 4: Closing wall не двигалась при drag
**Что случилось:** Closing wall сделали read-only для drag.  
**Эффект:** Пользователь не может перетащить замыкающую стену — нарушает UX "набросал на глаз".  
**Решение:** Closing wall тащится как любая другая через `updateMergeWallProperties`. Никакого `recalculateClosingWall()` после mouseUp — не нужен. `updateMergeWallProperties` уже поддерживает связность контура, комната остаётся закрытой. `recalculateClosingWall()` вызывается только из инпутов.

---

### Проблема 5: Цвет closing wall не менялся
**Что случилось:** Меняли цвет только в `lineWall` контейнере. `bodyWall` (fill + stroke через `drawShape`) оставался чёрным (`0x131313`).  
**Решение:** В `drawWall()` менять оба контейнера:
- `lineWall` — цвет линии
- `bodyWall` — fill `0xF0F0F0`, stroke `0x9E9E9E`, толщина 1px
Это касается любого визуального состояния стены (closing, warning, pinned).

## Пересмотренный план (после постмортема)

**Ключевые изменения относительно оригинального плана:**

| Шаг | Оригинальный план | Пересмотренный |
|-----|-------------------|----------------|
| Drag (Шаг 4) | Параллельный сдвиг + chain propagation | Свободный 2D (как было), chain propagation убрана |
| mouseUp | — | `recalculateClosingWall()` |
| Инпуты | Chain propagation | Chain propagation (без изменений) |
| Closing wall при drag | Read-only | Тащится свободно |

**Новый порядок:**
1. Closing wall: флаг `isClosing`, серый визуал — во время drag ведёт себя как любая другая стена
2. Инпут длины: `eventModifyWall` → chain propagation → `recalculateClosingWall()`
3. Инпут угла: `setActiveWallAngleByPoint0` → chain propagation → `recalculateClosingWall()`
4. Drag: без изменений относительно `c2602aa`, `recalculateClosingWall()` не вызывается

**Ключевое правило:**
```
Drag    → updateMergeWallProperties (old, без изменений)
          closing wall = просто ещё одна стена
          никакого recalculate

Инпуты  → chain propagation → recalculateClosingWall()
          только здесь closing wall вычисляется принудительно
```

`recalculateClosingWall()` — исключительно инпутный инструмент. Концепт closing wall нужен только для точного ввода, не для свободного drag.
