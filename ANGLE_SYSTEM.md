# Система углов 2D конструктора

## Цель

Этот документ фиксирует простую модель работы углов в 2D-конструкторе.

Главное правило:

**Изменение угла через input меняет выбранную стену, а вся остаточная невязка уходит в замыкающую стену.**

Без `pin`, без `anchor`, без сложного `chain propagation` как части продуктовой логики.

---

## Как понимать угол стены

У каждой обычной стены есть один редактируемый угол:

- угол задаётся в `points[0]`
- это угол между предыдущей стеной и текущей стеной
- для `closing wall` угол только отображается, но не редактируется

---

## Поведение при drag

При `drag` система углов не навязывает точную геометрию.

- пользователь свободно меняет форму комнаты
- углы могут меняться как часть свободного редактирования
- drag не должен запускать сложный пересчёт по input-модели

Иными словами:

**drag — это черновой режим**

---

## Поведение при input угла

При ручном вводе угла для обычной стены:

1. Меняется угол выбранной стены в её точке `points[0]`
2. Её собственная длина сохраняется
3. Остальные стены не меняют свои длины
4. Остальные стены не меняют свои собственные углы
5. Остальной контур может сместиться на плоскости как связанный хвост
6. После этого пересчитывается `closing wall`

То есть точный input угла не перерасчитывает всю комнату заново.  
Он делает локальное изменение и замыкает остаток через одну специальную стену.

---

## Поведение при input длины

Эта же логика относится и к длине:

1. Меняется длина выбранной стены
2. Её угол сохраняется
3. Остальные стены не меняют свои длины
4. Остальные стены не меняют свои углы
5. Остальной контур может только сместиться
6. `Closing wall` пересчитывается последней

---

## Closing Wall

`Closing wall` — единственная стена, которая поглощает геометрическую невязку после точного ввода.

Для неё:

- длина read-only
- угол read-only
- прямой ручной ввод запрещён

Смысл `closing wall` не в том, чтобы быть "ещё одной обычной стеной", а в том, чтобы показывать, насколько хорошо сошлись пользовательские измерения.

---

## Что важно для реализации

На уровне продукта важно только следующее:

- выбранная стена получает новое значение угла или длины
- остальные стены не теряют свою собственную геометрию
- замыкающая стена пересчитывается автоматически

Как именно внутри кода смещается оставшийся хвост — это уже техническая деталь реализации.

---

## Что не является целью

Этот документ не предполагает:

- solver для поиска "лучшей" конфигурации комнаты
- распределение ошибки по нескольким стенам
- поиск ближайшего `anchor`
- пользовательский `pin`
- обязательную квантизацию угла

Если такие механики когда-нибудь понадобятся, это будет отдельная версия концепции.  
Для текущей задачи они только усложняют модель.

---

## Критерий корректности

Система углов работает правильно, если пользователь видит предсказуемое поведение:

- мышкой можно свободно набросать комнату
- через input можно точно поправить нужный угол
- соседние стены не "ломаются" по своим размерам
- вся невязка уходит в `closing wall`

Это и есть целевая модель для текущей реализации.
